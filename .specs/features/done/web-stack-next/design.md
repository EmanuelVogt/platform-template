## 1. Repository layout after the feature

```
apps/
  api/
  web-vite/                 ← git mv apps/web (content byte-identical, package "web")
  web-next/                 ← new, package "web-next"
{% if web_stack == 'vite' %}apps{% endif %}/web   → symlink ../../apps/web-vite   (relative: ../apps/web-vite from the Jinja dir)
{% if web_stack == 'next' %}apps{% endif %}/web   → symlink ../apps/web-next
```

`copier.yml` deltas:

```yaml
_exclude:            # + two lines
  - apps/web-vite
  - apps/web-next
_tasks:              # + one entry, after `git init`, before `pnpm install`
  - command: node -e "const f='apps/web/package.json';const fs=require('fs');fs.writeFileSync(f,fs.readFileSync(f,'utf8').replace('\"name\": \"web-next\"','\"name\": \"web\"'))"
    when: "{{ web_stack == 'next' and _copier_operation == 'copy' and not _copier_conf.pretend }}"
web_stack:           # after app_domain
  type: str
  help: Stack do front headless (vite = React/Vite + TanStack Router; next = Next.js App Router)
  default: vite
  choices: [vite, next]
```

The rename task must run **before** `pnpm install` so the lockfile/workspace sees `web`.
Root `.prettierignore` gains `{% if*` (prettier would otherwise follow the symlinks and
format both shells twice). Root `.gitignore` unchanged. `pnpm-workspace.yaml` unchanged
(`apps/*` never matches the root Jinja dirs).

Repo-internal references to `apps/web` that must become stack-aware:

| File | Change |
| --- | --- |
| `apps/api/src/modules/module-boundaries.spec.ts:8` `WEB_SRC_DIR` | resolve first existing of `apps/web`, `apps/web-vite`; plus scan `apps/web-next` when present; kernel surface = `src/app/**` or `src/_app/**` |
| `lefthook.yml` | unchanged (`--filter=web` is the Vite shell in the repo and the only shell in a child) |
| `.github/workflows/catalog.yml` | `smoke` job: `turbo test:cov --filter=web-next` step + matrix (see § 5) |
| `apps/web-vite/Dockerfile`, docs | unchanged — they describe the child (`apps/web`) |

## 4. Dockerfile (Next)

```
FROM node:22-alpine AS base ; RUN corepack enable
FROM base AS pruner  ; COPY . . ; RUN pnpm dlx turbo@2 prune web --docker
FROM base AS builder ; COPY --from=pruner /app/out/json/ . ; COPY --from=pruner /app/out/pnpm-lock.yaml .
                       RUN pnpm install --frozen-lockfile ; COPY --from=pruner /app/out/full/ .
                       ARG NEXT_PUBLIC_API_URL ; RUN pnpm turbo build --filter=web
FROM node:22-alpine AS runner ; ENV NODE_ENV=production PORT=3000 HOSTNAME=0.0.0.0
                       RUN addgroup -S nodejs && adduser -S nextjs -G nodejs
                       COPY --from=builder --chown=nextjs:nodejs /app/apps/web/.next/standalone ./
                       COPY --from=builder --chown=nextjs:nodejs /app/apps/web/.next/static ./apps/web/.next/static
                       COPY --from=builder --chown=nextjs:nodejs /app/apps/web/public ./apps/web/public
                       USER nextjs ; EXPOSE 3000 ; CMD ["node", "apps/web/server.js"]
```

Mirror the Vite Dockerfile's pruner/builder stages exactly (same base image tags, same
pnpm invocation) — only the runner differs. `packages/api-client` must be built in the
builder stage the same way the Vite Dockerfile does it.

## 7. Risks

- Symlink + `git mv` are repo-structural: one exclusive task, first wave, so every later
  worker sees the final layout.
- Next 16 + vitest: `next/navigation` hooks need the app-router context in tests →
  `render-with-providers` mocks `next/navigation` (`usePathname`) via `vi.mock`.
- `turbo prune web` inside the Next child must include `packages/api-client` — same as Vite.
- Coverage ≥ 90 on a shell that is mostly copied code: specs are copied too.
