# Frontend architecture

Quick-read handbook for `apps/web`: React + Vite, TanStack Router and Query, React Hook Form +
Zod and the Kubb-generated `@platform/api-client`, organized by Feature-Sliced Design (FSD).
The template ships a **headless kernel** — transport, router shell, env, RFC 7807 helpers, an
access vocabulary — with no session, login or UI kit (the product picks one); business
features arrive as catalog entries. Contract, transport and routing rules always apply; slice,
form and UI-kit rules apply once the product builds on this stack. Code rules:
[`../code-quality.md`](../code-quality.md); tests: [`../test/testing.md`](../test/testing.md);
backend: [`back.md`](back.md); exceptions: ADRs ([`../adr/README.md`](../adr/README.md)). The
`feature-sliced-design` skill is the FSD base; this document states the project overrides.

## Layers and segments

| Layer       | Purpose                                           | May import from                     |
| ----------- | ------------------------------------------------- | ----------------------------------- |
| `app/`      | Bootstrap, providers, router, global styles       | every layer                         |
| `pages/`    | Routes; composes widgets, features and entities   | widgets, features, entities, shared |
| `widgets/`  | Reusable composed blocks                          | features, entities, shared          |
| `features/` | One user action (a form, a command)               | entities, shared                    |
| `entities/` | Domain model, one per backend module              | shared                              |
| `shared/`   | Config, libs, stores, UI compositions — no domain | nothing above it                    |

Segments: `ui/` (presentation), `model/` (hooks, stores, local schemas, orchestration), `api/`
(wrappers over generated hooks + query keys), `lib/`, `config/` — create only what the slice
needs. Not every layer is required: the template ships `app/`, `pages/` (home, error,
not-found) and `shared/` (`config/`, `lib/`, `store/`, `test/`); `entities/`, `features/` and
`widgets/` appear when the product or an installed catalog entry needs them, and `shared/` then
grows `ui/` (compositions, `ui/form/`), `types/` (branded ids) and `api/`. An entity never
knows another entity — composition happens in a widget, feature or page.

A catalog entry's web part (`web/core`, `web/react`) follows the raw-web rule so it stays
portable across web stacks: pure TypeScript in `core`, hooks and query options only in `react`,
no component, page or router; the allowlist is in [`../catalog/catalog.md`](../catalog/catalog.md).
`pnpm platform module add` copies it to `apps/web/src/entities/<entry>/`, after which it is an
ordinary entity; route, guard and form integration is the product's job, a recipe in the entry's
README. The app shell (`app/config`, `app/providers`, `app/router`) imports only the transport
client from `@platform/api-client` — no session type, permission or product schema enters it.

## Imports and slice isolation

Import directly from the file that defines the symbol (`@/` alias) — no aggregating `index`
barrels; this overrides FSD's "public API via `index`". Generated code likewise: one symbol per
subpath (`@platform/api-client/hooks/*`, `/zod/*`, `/models/*`), never the package root, never
re-exported by a front file. The only root-level import is the transport client in `app/config/`.

Layer direction and the sibling-slice veto are **lint errors** (`eslint-plugin-boundaries` via
`@workspace/eslint-config/fsd`): a layer imports only from layers below, a sibling slice is an
error, imports inside the same slice are free. The one declared exception is
`entities/*/api/*.keys.ts` — query keys are a public cross-entity surface because cache
invalidation crosses domains (Golden Rule 7). FSD's `@x` folders do not exist here: without
barrels there is nothing to re-export, every other entity-to-entity import is rejected, and a
reference to another entity's id uses a branded type in `shared/types/`. `import-x` covers
ordering, cycles, self-imports and duplicates; no-barrel is review. A pt-BR JSDoc on an export
consumed outside its slice only when the contract is not obvious from the signature.

## Data layer and state

- The contract truth is the backend Zod; `pnpm contract` regenerates `openapi.json` and the
  Kubb client. Never edit `generated/`; never retype a schema, type or enum that exists there.
- Each entity wraps the api-client tag of its backend module. Wrap when it adds invalidation,
  `select`, a per-endpoint `staleTime`/`gcTime` override or an error mapping; else re-export.
- Query keys in `entities/<resource>/api/<resource>.keys.ts` reuse the keys generated by Kubb:
  a hand-built key misses the hook's cache and invalidation becomes a silent no-op; the `all`
  entry is a label, not a prefix. Every mutation invalidates through the entity's keys.
- `staleTime`: short default in `app/query-client.ts`; lists longer; immutable data `Infinity`.
  Raise it per query; never lower the global defaults (a global `refetchOnWindowFocus: false`
  needs a documented reason). Derived data via `select`; polling via `refetchInterval`, never
  by hand; prefetch on link intent (router preload) and on hover (`prefetchQuery`).
- Transport headers (CSRF, correlation) belong to the api-client interceptor, never to
  operation parameters. `Idempotency-Key` is the caller's: a route that needs dedup exposes the
  header in the contract, the feature wrapper generates one value per manual attempt and reuses
  it on transport retries; only routes with a body are idempotent; the front never reads it.
- State: API data in TanStack Query through the entity; local visual state in
  `useState`/`useReducer`; shared client state (theme, sidebar) in Zustand under
  `shared/store/`; a form being edited in React Hook Form; derived data in `select`; filters,
  pagination and tabs in router search params. Server state never enters a global store: the
  kernel's `auth.store.ts` keeps only the redirect intent and the cross-tab logout channel.

## Bootstrap, transport and errors

`main.tsx` configures the api-client once (`baseURL` from env; `onUnauthorized` clears the
Query cache and navigates to login), persists the last protected location and renders
`AppProviders` (`QueryClientProvider` → cross-tab logout listener → `RouterProvider`). Env is
parsed from `import.meta.env` with Zod in `shared/config/env.ts`, failing fast at boot; `VITE_*`
is read nowhere else. Zod messages are pt-BR via `app/config/zod-locale.ts`, for generated and
local schemas alike. The transport (`packages/api-client/src/client.ts`) is one axios instance:
credentials, repeated-key array params, CSRF double-submit header on mutations, capture of the
`correlationId` from RFC 7807 error bodies. Never configure it from a component; never use
axios directly. The backend answers RFC 7807: branch on the problem `type`, never on status
code or message text — `shared/lib/problem-details.ts` narrows an unknown error (flat or
axios-wrapped) into `type`, `detail`/`title` and extension members. User-facing text never
leaks stack, SQL or paths; the `correlationId` is shown in support and toast surfaces.

## Routing and access control

- Routes are code-based `createRoute` trees in `app/router/`: `shell.tsx` owns the kernel
  routes (root, index redirect, authenticated pathless layout, home), `product-routes.tsx` is
  the product's extension point, `router.tsx` assembles them with default pending, not-found
  and error components. File-based routing is acceptable; `react-router-dom` is not.
- Paths come from `shared/config/routes.ts` (`ROUTES`), never raw strings; keys are English,
  URLs pt-BR. Protected paths form an allowlist; every untrusted destination (stored intent,
  last location) is validated against it — anti open-redirect.
- **`staticData.access` is mandatory on every route**: the augmentation in
  `app/router/access.d.ts` fails the typecheck without it. The vocabulary (`public`,
  `authenticated`, `permission` + key) is `shared/config/route-access.types.ts`; the kernel
  defines the shape only. The guard (a `beforeLoad` on the authenticated layout reading the
  leaf route's `access`) and the `ROUTE_ACCESS` table keyed by `RoutePath` come with the
  catalog entry that owns the session; redirect chain: stored intent → last protected location
  → home, never a loop. A mutable action is gated by a `useCan`-style hook from the session
  entity (review convention); nav items declare a permission; an empty section disappears.
- Code splitting per page: product routes load their page lazily; the initial bundle is app +
  shared + layout. Loading and error states are always handled (route pending component,
  error page whose retry invalidates the loader before resetting).

## Forms and validation

- `useForm` + `zodResolver`. Form shape equals the API body → the schema from
  `@platform/api-client/zod/*`; it differs (mask, string-to-number, discriminated union) → a
  local schema in `features/<action>/model/` with a `toBody()` transform, and the three-generic
  `useForm<Input, Context, Output>` whenever the schema has `.transform()` or `.coerce.*`.
- One form per entity for create and edit: a single component whose optional entity prop
  selects the mode; title, button and mutation switch on it; a field that exists in one mode
  is disabled in the other. Short form → drawer; long or multi-step → dedicated route.
- Controlled fields are a library in `shared/ui/form/` (`Rhf*`, one per file, generic over
  `FieldValues`, bound via `useController`, error read from `fieldState`). A missing field
  type is added there, never inline in a feature. Never read `field.ref` during render.
  Native date and time inputs are forbidden; the kit's picker components are used instead.
- Money is never free text: masked field, integer minor units in the form, converted at the
  boundary. A form model or editor reused by two or more features is an entity, never a feature.

## Contract enums and selects

- A value that exists in the contract (status, kind, category) is never typed by hand: the
  source is the const generated by Kubb in `@platform/api-client/models/*` (runtime object and
  type), not the zod schema, whose cast leaves `.options` untyped. One descriptor per enum, on
  the owning entity (`entities/<x>/model/<x>-labels.ts`), built with `defineEnum` from
  `shared/lib/`: a pt-BR label per value (mandatory), a badge color (optional); the full record
  makes a new contract member break the build. Divergence is `.override()`, a subset is
  `.pick()` — never a second map. Local schemas use `z.enum(generatedConst)`; pure-UI closed
  sets stay local literals. Gate: the `contract-enums` conformance spec (pre-push and CI), with
  the `contract-enum` harness hook warning at edit time; declared exceptions live in the spec.
- A select shows a label, never an id. The kit's `Select` is closed: it takes `items`
  (`{ value, label }` lists, never a record) and renders them itself, so the list on screen and
  the list that resolves the label are the same. A value missing from `items` is resolved by
  whoever owns the data (fetch by id, inject the current option); fallback labels are pt-BR
  text, never the identifier. The raw primitive is lint-restricted; multi-select is separate.

## Where does this go

| You are creating                                          | Put it in                                                                                                                                                  |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Domain-free primitive (button, input, dialog)             | the UI kit package (`packages/ui`)                                                                                                                         |
| App-specific composition; controlled form field           | `shared/ui/`; `shared/ui/form/` (`Rhf*`)                                                                                                                   |
| Entity component; form model/editor reused by 2+ features | `entities/<resource>/ui/`; `entities/<resource>/` (`model/` + `ui/`)                                                                                       |
| Composed block; user action or form                       | `widgets/<slice>/`; `features/<action>/`                                                                                                                   |
| Route                                                     | `pages/<slice>/` + `app/router/` + `ROUTES`                                                                                                                |
| Hook over one endpoint (+ invalidation)                   | `entities/<resource>/api/`                                                                                                                                 |
| Hook combining 2+ endpoints or UI orchestration           | `features/<action>/model/` or `widgets/<slice>/model/`                                                                                                     |
| Utility; env, paths, access; client store; ids            | `shared/lib/`; `shared/config/`; `shared/store/`; `shared/types/ids.ts`                                                                                    |
| Provider, `QueryClient`, router                           | `app/`                                                                                                                                                     |
| Naming                                                    | kebab-case files; PascalCase components and types; `use*` hooks; `use<Slice>Store`; `<resource>Keys`; `<action>Schema`; default export only in a lazy page |

## Golden Rules

1. A layer imports only from layers below it: `app → pages → widgets → features → entities → shared`.
2. A slice never imports a sibling slice; shared code moves up or down.
3. Deep import from the defining file; aggregating `index` barrels are forbidden.
4. `@platform/api-client` only in `entities/<resource>/api/`; exception: the transport client in `app/`.
5. Server state = TanStack Query; never duplicated in `useState` or a global store.
6. Forms: `useForm` + `zodResolver` with the api-client schema when the form shape equals the body.
7. A mutation invalidates queries through the entity's query keys.
8. `entities/<resource>/ui/` is dumb: receives the entity by prop, calls no API hook.
9. A page is a thin orchestrator; complex logic moves to a widget or feature.
10. Never edit `generated/`; regenerate with `pnpm contract`.
11. Env is parsed with Zod in `shared/config/env.ts`, failing fast at boot.
12. Code splitting per page.
13. api-client imports by symbol (`/hooks/*`, `/zod/*`, `/models/*`), never from the package root.
14. Transport headers belong to the api-client interceptor; `Idempotency-Key` is the caller's, per operation.
15. Lint: `import-x` + `unused-imports` + `boundaries` — layer direction and sibling slice are lint errors; `*.keys.ts` is the declared exception; no-barrel is review.
16. Router = TanStack Router; routes live in `app/router/`.
17. An entity wrapper exists only when it adds invalidation, `select`, transform or error mapping; otherwise re-export.
18. `Idempotency-Key` = one value per manual attempt, generated by the feature wrapper, reused on transport retry.
19. The correlation id is transport-owned: captured from the RFC 7807 envelope by the api-client, never produced by a feature.
20. Shared id types are branded and live in `shared/types/ids.ts`.
21. `useForm<Input, Context, Output>` whenever the schema has `.transform()` or `.coerce.*`.
22. One form per entity for create and edit (mode by optional entity prop); short form in a drawer, long or multi-step on its own route.
23. A contract enum is never retyped and has one descriptor, on the owning entity, derived from `models/*`; `.override()` to diverge, `.pick()` for a subset. Gate: `contract-enums` spec.
24. Form fields come from `shared/ui/form/` (`Rhf*`), controlled, no `field.ref` in render; native date/time inputs are forbidden.
25. A select shows a label, never an id; the kit's `Select` is closed over `items`; fallback text is pt-BR, never the identifier.
26. `sr-only` requires a positioned ancestor (`isolate` does not count). Gate: lint rule `platform/sr-only-requires-positioned-ancestor`.

## Stack (fixed majors)

Core: `react ^19`, `react-dom ^19`, `vite ^8`, `@vitejs/plugin-react ^6`, `typescript ~6`. Data:
`@tanstack/react-query ^5`, `@platform/api-client` (Kubb 3, `axios ^1`). Form: `react-hook-form ^7`,
`@hookform/resolvers ^5`, `zod ^4`. Router: `@tanstack/react-router ^1`. State: `zustand ^5`. UI: the
product's choice. Lint: `eslint ^10`, `typescript-eslint`, `import-x`, `unused-imports`, `boundaries`,
`react`, `react-hooks`, `jsx-a11y`. Tests: `vitest ^4`, Testing Library, `msw ^2`. Majors are fixed;
minor and patch move through Renovate.
