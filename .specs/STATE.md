| AD-001 | superseded by AD-013 (v1) | **Product slot files.** Contract-facing closed sets (permission catalogs, access profiles, upload profiles) are extended through *static slot files* the platform ships empty and the product fills with additive one-liners: `shared/kernel/access/product-permission-catalogs.ts` (precedent), `shared/kernel/access/product-access-profiles.ts`, `shared/kernel/upload/product-upload-profiles.ts`. They are static because the Zod contract (`z.enum`) is evaluated at import time and must reach `openapi.json` → Kubb → web with literal types. Slot files are the only platform files a product edits, alongside the composition root (`app.module.ts`, `db/schema.ts`, `product-routes.tsx`); the platform never adds content to them after creation, so `copier update` 3-way merge stays clean. Behaviour that is only needed at boot (notification template sources, audit registrations) uses **runtime registries** the product fills from its own module (`OnModuleInit`), never a slot file. |
| AD-002 | superseded by AD-014 (v1) | **`professional` stays a base-set access profile in v0.2** (`master`, `admin`, `professional`).
