# Prettier Format Gate Specification

## Problem Statement

`prettier` cannot run in this repository. `.prettierrc:8-10` loads
`prettier-plugin-tailwindcss` and points `tailwindStylesheet` at
`packages/ui/src/styles/globals.css` — a package that does not exist here and a
Tailwind that is installed nowhere in the tree. Every invocation dies with ENOENT
before formatting a single file, and `.prettierrc` is copied verbatim into every
generated product. Nothing calls prettier — `format:check` (`package.json:11`) is
invoked by no hook, no workflow and not by `release-preflight.mjs` — so the
breakage stayed silent since the pre-catalog era. Recorded as a follow-up on
2026-08-22 (`STATE.md:57`) and as High in
`docs/platform_template/audit-2026-08-23.json:309`.

## Goals

- [ ] `pnpm format:check` exits 0 in this repo and in a freshly generated product.
- [ ] An unformatted file cannot reach `main` unnoticed.
- [ ] A generated product inherits a working config and no red pipeline.

## Out of Scope

| Feature | Reason |
| --- | --- |
| Reinstating Tailwind or a `packages/ui` | The catalog model puts UI in an entry, never in the kernel (AD-013); no entry ships it |
| The formatting rules themselves (`semi`, `printWidth`, …) | Current `.prettierrc` values stay as they are; this feature only makes them run |
| ESLint ↔ prettier overlap | `packages/eslint-config` is untouched |
| Reformatting a child's own tree | The child owns its code; the template ships configuration, not a reformat |

## User Stories

### P1: Prettier runs again ⭐ MVP

**User Story**: As a maintainer of the template, I want `prettier` to execute, so
that formatting is a tool I can run instead of a config that throws.

**Why P1**: Every other requirement here is unreachable while the binary dies on
load.

**Acceptance Criteria**:

1. WHEN `pnpm format:check` runs at the repo root THEN it SHALL exit without a
   plugin-load or ENOENT error.
2. WHEN `.prettierrc` names a filesystem path THEN that path SHALL exist in the
   repo, asserted by a committed test so the defect class cannot return.
3. WHEN a product is generated by copier and its dependencies are installed THEN
   `pnpm format:check` in that product SHALL exit 0.

**Independent Test**: `pnpm format:check` in a clean checkout, and the same
command inside the tree `pnpm template:smoke` renders.

---

### P1: The tree is formatted ⭐ MVP

**User Story**: As a maintainer, I want the repo to already satisfy its own
formatting rules, so that the gate reports real regressions instead of a backlog.

**Why P1**: A gate over an unformatted tree is red on day one and gets disabled.

**Acceptance Criteria**:

1. WHEN `pnpm format:check` runs after the reformat THEN it SHALL report zero
   differing files.
2. WHEN the checked set is resolved THEN it SHALL cover every extension the repo
   authors and prettier parses — `ts`, `tsx`, `mts`, `mjs`, `js`, `json`, `yml`,
   `css` — and SHALL exclude `*.jinja`, `docs/platform_template/` and generated
   trees.
3. WHEN the reformat touches `catalog/**` THEN the commit SHALL satisfy the
   `advisory-required` hook without inventing an advisory.

**Independent Test**: `pnpm format:check` exits 0; `git log -1` of the catalog
commit shows the trailer; a file of each covered extension appears in the diff.

---

### P2: It cannot rot again

**User Story**: As a maintainer, I want the formatting to be enforced by a gate,
so that the next drift is caught in minutes instead of two years.

**Why P2**: The repair holds without it; only the recurrence does not.

**Acceptance Criteria**:

1. WHEN a commit stages a file of a covered extension that is not formatted THEN
   the pre-commit hook SHALL fail or fix it before the commit lands.
2. WHEN CI runs on `main` THEN a format check SHALL run and SHALL fail the build
   on an unformatted file.
3. WHEN a product is generated from the template THEN its pipeline SHALL NOT fail
   on the formatting of code the template did not ship.

**Independent Test**: stage a deliberately unformatted file and observe the hook;
push a branch with one and observe CI; run `pnpm template:smoke` and inspect the
generated pipeline.

---

## Edge Cases

- WHEN a `*.jinja` file is encountered THEN it SHALL be skipped — prettier cannot
  parse Jinja delimiters.
- WHEN `pnpm-lock.yaml` or `packages/api-client/generated/**` is encountered THEN
  it SHALL stay ignored.
- WHEN a child runs `copier update` onto the fixed `.prettierrc` THEN no manual
  migration step SHALL be required (AD-034: a non-major ships zero manual steps).
- WHEN the reformat rewrites a file that a `.claude/hooks` tripwire guards
  (`docs/`, `CLAUDE.md`, `AGENTS.md`) THEN the run SHALL NOT depend on disabling
  that hook.
