# Code discovery

Looking for code is the biggest context expense in this repo — measured, 87% of
all shell output, against 1% for tests. This skill is what makes search cheap and
what avoids the two wrong answers `grep` gives with a confident face.

## Where things live

- `apps/api/src/modules/<module>/` — modular monolith, 19 modules. Layers:
  `domain/entities`, `application` (use cases), `infrastructure`, `api`.
- `apps/web/src/` — Feature-Sliced Design: `app`, `pages`, `widgets`, `features`,
  `entities`, `shared`. **No barrels**: the symbol comes from the file that defines
  it, so a consumer's import already hands you the exact path.
- `packages/` — `api-client` (generated by Kubb), `ui`, configs.
- Structural decisions in `.ca-plans/DECISIONS.md`; business vocabulary in `docs/CONTEXT.md`.

Confirm on disk before stating anything (`ls apps/api/src/modules`) — a memorized
inventory goes stale, and this file is not an inventory.

## How to search cheaply

- Use `grep`, **never `rg`**: the rtk proxy compresses `grep`'s output and ignores
  `rg` entirely (`exclude_commands`, see [`../agent-harness/SKILL.md`](../agent-harness/SKILL.md)).
- `grep -rl` first to know *where*, and only then open the snippet. A broad
  `grep -rn` dumps content that won't get used and sits in the context until the end.
- Start from a consumer when you can: one import line answers "where is this
  defined" with no search at all.

**Never open a large file whole:** `openapi.json` (~255k tokens),
`pnpm-lock.yaml` (~184k), `packages/api-client/generated/index.ts` (~74k),
`apps/api/drizzle/migrations/meta/*_snapshot.json` (~72k each) and a large module's
integration fixtures (~57k each). Reading one of those costs more than the peak of
a whole session. A range (`offset`/`limit`), `grep -n` or `head` still work fine —
what doesn't work is the whole file. In Claude Code, one hook blocks this by size
(`no-huge-reads.mjs`) and another blocks direct navigation in the main agent from
the turn's third call onward, routing it to the `repo-scout` subagent
(`delegate-to-subagent.mjs`); in Cursor and Codex, you are the safeguard.

## The two blind spots grep has here

Static analysis — including a code-graph tool — sees **import**. The two
couplings that matter most in this project are not import:

1. **The api→web contract is generated by the build.** The front imports
   `@platform/api-client` in hundreds of files, but the package's `exports` point
   to `./dist/*`, which isn't versioned. The link api → `openapi.json` → Kubb → web
   doesn't exist in the source. For "I changed the contract, what breaks on the
   front," the answer is `pnpm contract:consumers <operationId>` and
   `pnpm contract:diff` — not grep.

2. **Authorization is wired by metadata at runtime.** The guard reads the key via
   `Reflector`; whoever *implements* the rule doesn't import its decorator.
   Searching by the decorator's name returns the usages and hides the
   implementation.

Measured: on a question of that second kind, `grep` returned 136 files in 12k
chars and a code graph returned 132 in 43k — 3.6x more expensive and missing the
piece that implemented the rule. That's why there's no graph tool here.

## What a discovery returns

`file:line` plus one sentence of what's there. Nothing beyond that.

No pasting file content, no explaining the architecture to whoever asked, no
recommending a solution. Three paths that answer = three lines.

Didn't find it? Say so and say where you looked. An honest "it doesn't exist" is
worth more than a guess that sends whoever asked to the wrong file.

**Why this is so lean:** when discovery runs in a subagent, everything it returns
gets re-paid in the caller's context on every following turn. The value of
delegation is the main context getting the map, not the trip.
